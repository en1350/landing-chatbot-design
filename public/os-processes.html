📘 Теоретический материал

1. Понятие процесса

Процесс — программа, находящаяся в стадии выполнения, со своим контекстом: адресным пространством, регистрами ЦП, открытыми файлами и состоянием.

Состояния процесса (5-модель):

  • New — создаётся
  • Ready — готов к выполнению, ждёт ЦП
  • Running — выполняется на процессоре
  • Waiting / Blocked — ждёт событие (ввод-вывод, семафор)
  • Terminated — завершён

2. Дескриптор процесса (PCB)

Каждому процессу соответствует Process Control Block, содержащий: PID, состояние, счётчик команд (PC), регистры ЦП, информацию о планировании, учёт памяти и ввода-вывода.

3. Создание и завершение процессов

# Linux: создание процесса fork() // создаёт дочерний процесс (копия родителя) exec(...) // заменяет образ процесса новой программой exit(n) // завершает процесс с кодом n wait(...) // родитель ждёт завершения дочернего

4. Планирование процессов

Планировщик выбирает процесс из очереди готовых. Критерии:

  • Загрузка ЦП (CPU utilization)
  • Пропускная способность (throughput)
  • Время оборота (turnaround time)
  • Время ожидания (waiting time)
  • Время отклика (response time)

Алгоритмы: FCFS, SJF, Round Robin, приоритетное планирование, многоуровневые очереди.

5. Синхронизация и взаимное исключение

Для доступа к общим ресурсам используются: семафоры, мьютексы, мониторы. Классическая задача — «критическая секция».

6. Тупики (Deadlock)

Тупик — ситуация, при которой каждый процесс из набора ждёт событие, которое может вызвать только другой процесс из этого набора.

4 условия Коффмана (все должны выполняться одновременно):

  1. Взаимное исключение
  2. Удержание и ожидание
  3. Отсутствие вытеснения
  4. Циклическое ожидание

Методы работы: игнорирование (страус), предотвращение, избегание (алгоритм банкира), обнаружение + восстановление.

🛠️ Практические задания

Изучите примеры работы с процессами. Это подготовит вас к контрольным задачам.

Практика 1. Анализ вывода ps в Linux

USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND root 1 0.0 0.1 169344 13000 ? Ss Oct05 0:03 /sbin/init root 412 0.2 0.5 450000 42000 ? Sl Oct05 0:15 /usr/bin/Xorg user 1823 95.3 1.2 820000 98000 pts/0 R+ 10:30 12:45 ./compute user 2001 0.0 0.0 0 0 ? Z 10:32 0:00 [defunct]

Вопросы для самопроверки:

  • Какой процесс потребляет больше всего ЦП? → PID 1823 (95.3%)
  • Что означает STAT=Z у процесса 2001? → «зомби» — завершён, но ждёт wait() от родителя
  • Какой процесс является предком всех? → PID 1 (/sbin/init)

Практика 2. Расчёт времени ожидания (FCFS)

Процессы приходят в порядке P1 (0), P2 (2), P3 (4), длительности: 8, 4, 1 мс.

P1 стартует в 0 (ожидание 0), P2 стартует в 8 (ожидание 8 − 2 = 6), P3 стартует в 12 (ожидание 12 − 4 = 8). Среднее = (0+6+8)/3 = 4.67 мс.

Практика 3. Проверка тупика по алгоритму банкира

Доступно ресурсов: (3,3,2). Проверяем, существует ли безопасная последовательность — перебираем процессы, у которых Need ≤ Available, и «возвращаем» их Allocation.

📝 Контрольные задачи (3 задачи × 5 баллов)

Максимум: 15 баллов. Итоговая оценка по 5-балльной шкале.

Задача 1. Процессорное время (алгоритм SJF)

Даны 4 процесса с временем выполнения (мс):

P1=6, P2=8, P3=7, P4=3. Все прибыли одновременно (время 0).

Применяется алгоритм SJF (Shortest Job First) без вытеснения. Чему равно среднее время ожидания?

Задача 2. Анализ системного вывода

Фрагмент вывода команды top в Linux:

Какое из утверждений НЕВЕРНО?

Задача 3. Проблема тупика

Система имеет 12 устройств ввода-вывода одинакового типа. Три процесса:

  • P1: удерживает 4, максимум нужно 8
  • P2: удерживает 3, максимум нужно 6
  • P3: удерживает 3, максимум нужно 4

Свободно: 12 − (4+3+3) = 2 устройства. Какая из последовательностей завершения процессов безопасна?
