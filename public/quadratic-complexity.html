1 Бизнес-контекст

Реальная задача: найти пары платежей, которые вместе дают нужную сумму (сверка транзакций).

💳
Задача: в списке платежей найти все пары, сумма которых равна заданной (например, парный возврат).
Вход: массив arr из n сумм и число target.
Риск: «в лоб» код проверяет каждую пару. На 1 000 платежей это терпимо, на 100 000 сервис «зависает».

2 Теория: откуда берётся n²

Как отличить квадратичную сложность от линейной по виду кода.

1. Вложенный циклВнешний цикл делает n шагов, и на каждом внутренний тоже до n шагов. Итого n · n = n² операций.
2. Внутренний цикл от i+1Сумма (n−1)+(n−2)+…+1 = n(n−1)/2. Это половина n², но константу 1/2 отбрасываем: всё равно O(n²).
3. Рост в 100 разУвеличили данные в 10 раз — время выросло в 100 раз. Это главный признак квадратичной сложности.
4. Лучшего и худшего случая нетЕсли нет досрочного выхода, countPairs всегда делает ровно n(n−1)/2 сравнений.
💡 Ключевой вывод: считаем не циклы, а как они связаны. Вложены друг в друга, и оба зависят от n, значит сложности перемножаются: O(n) · O(n) = O(n²).

6 Примеры решений: пара с заданной суммой

    
Задача: есть ли в массиве два числа, сумма которых равна target.


    

      
Плохо Подход 1: Два вложенных цикла

      
function hasPair(arr, target) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] + arr[j] === target) return true;
    }
  }
  return false;
}

      
Время: O(n²)Память: O(1)

      
Просто и надёжно, подходит для небольших массивов (сотни элементов). На больших данных быстро становится узким местом.

    


    

      
Компромисс Подход 2: Сортировка + два указателя

      
function hasPair(arr, target) {
  const a = [...arr].sort((x, y) => x - y);
  let l = 0, r = a.length - 1;
  while (l < r) {
    const s = a[l] + a[r];
    if (s === target) return true;
    if (s < target) l++; else r--;
  }
  return false;
}

      
Время: O(n log n)Память: O(n)

      
Сортировка стоит n log n, а сам поиск за один проход — O(n). Побеждает самое дорогое: O(n log n).

    


    

      
Оптимально Подход 3: Хэш-таблица

      
function hasPair(arr, target) {
  const seen = new Set();
  for (const x of arr) {
    if (seen.has(target - x)) return true;
    seen.add(x);
  }
  return false;
}

      
Время: O(n)Память: O(n)

      
Вместо внутреннего цикла — мгновенный поиск в Set за O(1). Платим памятью за скорость (Space-Time Tradeoff).

    

  


  

    
7 Code Review: типичная ошибка Junior'ов

    
Две ошибки в разные стороны: «два цикла — всегда n²» и «внутренний цикл короче — значит быстрее порядка».

    

      

        
✗ Junior-ответ

        
«В функции два цикла for, значит сложность O(n²).»

        
for (let i = 0; i < n; i++) { a(i); }
for (let j = 0; j < n; j++) { b(j); }

        
Почему это ошибка: циклы идут друг за другом, а не друг в друге. Складываем: n + n = 2n → O(n).

        
Квадрат даёт только вложенность двух циклов, зависящих от n.

      

      

        
✓ Senior-ответ

        
«Циклы вложены, оба зависят от n. Внутренний стартует с i+1, значит сравнений n(n−1)/2. Константу 1/2 и младший член отбрасываем: O(n²).»

        
Обратный случай: если внутренний цикл выполняется константное число раз (j < 3), это n · 3 = O(n), хотя циклы вложены.

        
Смотрите на то, от чего зависит число итераций каждого цикла.
