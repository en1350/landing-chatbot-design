1 Бизнес-контекст

Зачем вообще искать максимум? Реальная задача — мониторинг пиковой нагрузки на сервер за отчётный период.

📊
Задача: найти пиковое значение нагрузки на сервер за отчётный период (сутки/неделя).
Вход: массив arr — замеры CPU / RAM / RPS по минутам.
Требование: один проход по массиву, без дополнительной памяти — данные могут быть огромными (сотни тысяч точек).

2 Теория: как анализировать сложность кода

Пошаговый чек-лист для определения Big-O любой функции.

1. Определите входные данные (n) Обычно это длина массива, количество узлов в дереве или число символов в строке. Для findMax это n = arr.length.
2. Посчитайте базовые операции Присваивание, арифметика, сравнение, доступ по индексу — всё это O(1). Сложите их количество внутри цикла.
3. Найдите доминирующий член При больших n младшие члены и константы не влияют на рост. 3n + 5 превращается в n.
4. Оцените худший случай (Worst Case) Big-O по умолчанию описывает верхнюю границу. Для findMax худший, средний и лучший случаи одинаковы: всегда n-1 сравнений.
💡 Ключевой вывод для findMax: Мы делаем 1 инициализацию + (n-1) итераций. На каждой итерации: 1 сравнение + (возможно) 1 присваивание. Обе операции O(1). Итого: O(1) + (n-1)·O(1) = O(n).

5 Примеры решений: поиск дубликатов в массиве

    
Чтобы понять ценность O(n), сравним три подхода к классической задаче: «Есть ли в массиве повторяющиеся элементы?». Вход: массив из n чисел.


    

      
Плохо Подход 1: Вложенные циклы (Brute Force)

      
function hasDuplicates(arr) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] === arr[j]) return true;
    }
  }
  return false;
}

      

        Время: O(n²)
        Память: O(1)
      

      

        Пояснение: Для каждого элемента мы пробегаем весь оставшийся массив. При n=10 000 это ~50 000 000 операций.
        
    
          
  • Плюс: Не требует дополнительной памяти.
    • 
          
  • Минус: Катастрофически медленно на больших данных. Типичная ошибка Junior-разработчика.
    • 
        

      

    


    

      
Компромисс Подход 2: Сортировка + линейный проход

      
function hasDuplicates(arr) {
  arr.sort((a, b) => a - b); // Сортировка
  for (let i = 1; i < arr.length; i++) {
    if (arr[i] === arr[i - 1]) return true; // Линейный проход O(n)
  }
  return false;
}

      

        Время: O(n log n)
        Память: O(1) или O(n) (зависит от алгоритма сортировки)
      

      

        Пояснение: Мы упорядочиваем массив, после чего дубликаты гарантированно стоят рядом. Остаётся сделать один линейный проход (тот самый O(n)!), сравнивая соседние элементы.
        
    
          
  • Плюс: Значительно быстрее вложенных циклов.
    • 
          
  • Минус: Изменяет исходный массив (побочный эффект), сортировка всё ещё медленнее чистого O(n).
    • 
        

      

    


    

      
Оптимально Подход 3: Хэш-таблица (Set)

      
function hasDuplicates(arr) {
  const seen = new Set();
  for (let i = 0; i < arr.length; i++) { // Один проход O(n)
    if (seen.has(arr[i])) return true;   // Поиск в Set: O(1)
    seen.add(arr[i]);                    // Вставка в Set: O(1)
  }
  return false;
}

      

        Время: O(n)
        Память: O(n)
      

      

        Пояснение: Мы делаем ровно один линейный проход по массиву. Проверка наличия элемента в Set и добавление в него работают за O(1) в среднем.
        
    
          
  • Плюс: Максимально быстрое время выполнения. Идеально для продакшена.
    • 
          
  • Минус: Мы жертвуем памятью (O(n)), создавая новую структуру данных. Это классический Space-Time Tradeoff (компромисс между памятью и скоростью).

6 Code Review: типичная ошибка Junior'ов

    
Частая ошибка на собеседовании — указать O(n²) «потому что есть цикл». Разберём, почему это неверно для findMax.

    

      

        
✗ Junior-ответ

        
«Сложность O(n²), потому что в функции есть цикл for.»

        
Почему это ошибка: квадратичная сложность O(n²) возникает только при вложенных циклах (как в Подходе 1 выше). У нас один цикл, и он делает одну операцию за итерацию → O(n).

        
Запомните: один цикл = O(n), два вложенных = O(n²), три = O(n³).

      

      

        
✓ Senior-ответ

        
«Сложность O(n): один цикл по массиву длины n, внутри — одно сравнение и возможное присваивание (обе операции O(1)). Итого: n · O(1) = O(n).»

        
Пространственная сложность O(1): используются только две скалярные переменные — max и i. Их объём не зависит от n. Дополнительная память не аллоцируется (в отличие от подхода с Set).

        
Это оптимальный алгоритм: нижняя граница задачи Ω(n) — чтобы найти максимум, нужно хотя бы один раз посмотреть на каждый элемент.
